# Fall back when the IPC runtime directory is unavailable

Upstream: [microsoft/vscode#336162](https://github.com/microsoft/vscode/pull/336162), fixing [issue #336161](https://github.com/microsoft/vscode/issues/336161).

State on 2026-09-14: **OPEN**. Snapshot head: `a5eab6ad66c3ecbd17f26b2528734ca778d5a60d`. Source base: `bd0cd43cd7bf3a3c6bd721f729df97fbb7265d58`.

[Download source patch](../../source-patches/vscode/336162.patch) · [Current upstream patch](https://github.com/microsoft/vscode/pull/336162.patch)

When `XDG_RUNTIME_DIR` is set but missing or unusable, the agent host can fail to bind its IPC socket. In WSL after a reboot, this prevented saved agent sessions from appearing even though their transcripts remained on disk. The source change checks the runtime directory before selecting it and otherwise uses the existing temporary-directory fallback.

The affected Node IPC test file passed all 26 tests after transpilation. Targeted ESLint and `git diff --check` passed. A full client type check did not complete because the WSL instance was under memory pressure. The fix has not been validated against an installed VS Code bundle or in a live UI. No combined-installer entry is included.
