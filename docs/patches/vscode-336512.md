## Root cause and regression check

Codex 0.154 emits `request_user_input_async` as an agent message with `delivery: async` and a structured questions array. VS Code's ordinary message mapper turns this into Markdown without creating an input request. The question and suggested choices therefore appear as text.

The dispatcher extracted directly from the original vendor server archive reproduces the failure. The installed Windows and Ubuntu bundles reproduce it before this patch as well. The prior feedback-review patch modifies editor comment commands and their loading-error UI, not this server dispatch path. This is missing support in the integration, not a regression caused by that patch.

## Behavior

The adapter uses the existing question carousel, allowing suggested answers or free text. Asking does not stop the native agent. If native work finishes first, the host conversation remains waiting for an explicit answer or skip so the existing controls remain usable. Answers use native start-or-steer with sticky thread settings. A late answer can start a continuation within the same host conversation turn.

The controller deduplicates live item events, never automatically submits a suggested answer, cancels stale controls, and reopens questions on delivery failure. Stop waits for an in-flight answer RPC before interrupting the actual continuation. RPC responses and native turn-start notifications may arrive in either order. New ordinary prompts replace stale question controls. Restored transcript messages remain history; this change does not reconstruct pending controls after an agent-host process restart.
